GUIDED PRACTICE / 02 C

把規則拆開，
讓不同入口共用。

把巡檢驗證與統計拆成可重用的模組，讓瀏覽器、Node.js 命令列與測試共用同一份規則。再認識 package.json、npm scripts 與 package-lock.json；本課刻意不加入第三方依賴。

更新：2026-11-23 · 八個步驟 · 三個修改練習

準備與範例入口

  • 先完成第 2 階段 A／B，能分辨資料驗證與畫面更新。
  • 需已安裝 Node.js 與 npm。範例要求 Node.js 20 以上；本次實測 Node.js 24.12.0、npm 11.6.2，沒有宣稱已逐版測試。
  • 將 examples/modules-npm 整個資料夾複製到自己的練習位置，再在該副本開啟終端機。本課不在教材根目錄建立 npm 專案。
  • 沒有第三方套件；demo、test、serve 可直接執行，不必先安裝依賴。若 PowerShell 的 npm.ps1 被執行政策擋下，可使用 npm.cmd，無須為本課調整全域政策。

先在自己的範例副本執行 npm run serve，從印出的 HTTP 網址操作；命令列 demo 與測試則直接在終端機執行。

1. 先畫出責任，再拆檔案

閱讀 inspection.js、app.js、cli.js、inspection.test.js。用箭頭畫出三個入口都匯入 inspection.js；sample.js 提供相同的三筆虛構資料。先找出哪個檔案碰 DOM，哪個檔案只做資料處理。

預期觀察

inspection.js 不使用 document 或 localStorage，因此能在不同執行環境重用。app.js 負責瀏覽器畫面；cli.js 負責命令列輸出。相同 JavaScript 語法不代表所有瀏覽器與 Node.js API 都能互換。

2. 用 export 明確公開能力

找出 inspection.js 的 parseInspections 與 summarize。第一個函式處理 JSON 與資料契約，第二個只接收驗證後的清單並計數。不要把 DOM 更新塞回共用模組。

預期觀察

具名匯出告訴其他檔案可以使用哪些能力。模組不是把長程式任意切開；要讓責任與相依關係更清楚。summarize 的前提是輸入已通過驗證。

export function summarize(rows) {
  return {
    total: rows.length,
    normal: rows.filter(row => row.result === '正常').length,
    abnormal: rows.filter(row => row.result === '異常').length
  };
}

3. 用 import 接起 Node.js 入口

在範例副本執行 node cli.js，對照 cli.js 中的相對匯入路徑。注意 ./ 與 .js 副檔名。再把 sample.js 的一筆正常改成異常，重新執行並觀察。

預期觀察

原版輸出 total: 3、normal: 2、abnormal: 1。修改資料後統計應隨之改變。package.json 的 type: module 明確讓 Node.js 將這個套件範圍的 .js 視為 ES 模組。

import { parseInspections, summarize } from './inspection.js';
import { sampleBackup } from './sample.js';

const rows = parseInspections(JSON.stringify(sampleBackup));
console.log(JSON.stringify(summarize(rows), null, 2));

4. 在瀏覽器使用相同規則

執行 npm run serve，開啟印出的本機 HTTP 網址。用 Network 找 app.js、inspection.js 與 sample.js，確認 JavaScript 回應。編輯 JSON 再按驗證；語法錯誤不應清空有效結果。

預期觀察

HTML 的 script type=module 控制瀏覽器模組載入；瀏覽器不靠 package.json 的 type 判斷這個 script。直接以 file: 開啟常會遇到模組載入限制，應使用 HTTP。本課提供的 Node.js 小服務只綁定 127.0.0.1。

<script type="module" src="app.js"></script>

5. 讀懂 npm scripts

先執行 npm run 看可用命令，再執行 npm run demo、npm test。閱讀 package.json 的 scripts，對照實際執行的 Node.js 指令。若 8080 已被使用，可改為 npm run serve -- --port 8081。服務使用完按 Ctrl+C。

預期觀察

npm 是專案工具與套件管理介面；本課的 scripts 只是清楚命名的命令入口，不會自動把 JavaScript 變成前端框架。private: true 防止此範例被 npm 意外發布；不是資料保密或權限隔離機制。

{
  "name": "web-learning-modules-lab",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "description": "Dependency-free teaching example for shared browser and Node.js modules",
  "scripts": {
    "demo": "node cli.js",
    "test": "node --test",
    "serve": "node serve.js"
  },
  "engines": {"node": ">=20"}
}

6. 修改規則，也修改驗收

執行 npm test，原版應有 10 個通過的測試。在自己的副本故意移除名稱的 trim，再觀察測試失敗；修回後重跑。接著完成下方一個修改題。

預期觀察

同一份資料模組在測試與瀏覽器中被重用。測試可攔住已寫出的規則回歸，但不能保證所有需求都正確，也不能取代實際介面驗收。

npm test
# Windows PowerShell 如擋住 npm.ps1，可改用
npm.cmd test

7. 看懂鎖定檔的範圍

對照 package.json 與 package-lock.json。再只在自己的範例副本執行下方離線 ci 命令。此命令會清理該專案的 node_modules，需先確認終端機位置正確。

預期觀察

npm ci 需要鎖定檔，依既有安裝資訊執行，不以更新鎖定檔作為修正不一致的方法。本課沒有外部依賴，鎖定檔只記錄本專案資訊；這次離線成功不代表任意有依賴的專案也能在空快取離線安裝。

# 只在自己的範例副本執行，先確認目前資料夾
node --version
npm --version
npm ci --ignore-scripts --offline --audit=false --fund=false
# 本命令略過安裝生命週期 scripts；npm test 是之後明確執行的另一個命令。

8. 把可重現的條件寫下來

記錄自己的 Node.js／npm 版本、執行命令與實際結果。將 package.json、package-lock.json、原始碼與測試一起納入自己的 Git 變更，先看差異再提交；node_modules 不加入版本庫。

預期觀察

鎖定檔固定依賴解析資訊，但不固定 Node.js、作業系統、原生元件或所有環境設定。新增或更新套件仍應理解變更；本課沒有下載第三方套件，也沒有建立完整建置工具鏈。TypeScript 留到下一課。

自己動手修改

A. 增加異常比例

在自己的副本讓 summarize 多回傳 abnormalRate。空清單回 0，三筆中一筆異常回 1/3。先補測試，再修改模組及瀏覽器呈現。

完成操作後看解答

可由 rows.length === 0 ? 0 : abnormal / total 推導，避免除以零。Node.js 的摘要物件測試需補上新欄位；瀏覽器也要新增呈現欄位，不能只在模組加回傳值就宣稱介面已支援。

B. 找出錯誤匯入的位置

在自己的副本把 cli.js 的 ./inspection.js 改成不存在的檔名，再執行 npm run demo。閱讀錯誤後修回。不要改已驗證的其他入口。

完成操作後看解答

錯誤發生在模組解析／載入，尚未執行巡檢驗證。先檢查相對路徑、檔名、大小寫與副檔名；不要把所有匯入失敗都當成資料 JSON 壞掉。

C. 缺少鎖定檔會怎樣？

只在另一份練習副本暫時移開 package-lock.json，再執行 npm ci --ignore-scripts --offline --audit=false --fund=false。記錄結果後恢復鎖定檔。

完成操作後看解答

npm ci 應拒絕缺少可用鎖定檔的專案。它不是 npm install 的完全同義詞；也不應靠手動刪改鎖定檔掩蓋依賴不一致。此練習不新增外部套件。

完成檢核

  • 能畫出三個入口與共用模組的匯入關係。
  • 瀏覽器與 Node.js 使用同一份驗證／統計規則，原版統計為 3／2／1。
  • 可執行 npm run demo、npm test，並說明 scripts 對應的指令。
  • 能分辨 Node.js 的 package type 與 HTML 的 script type=module。
  • 知道 npm ci 需要鎖定檔、可能清理 node_modules，且零依賴離線案例的適用範圍有限。
  • 完成至少一個修改題並留下命令、測試結果與環境版本；未更動主教材進度。

本課不自動修改主教材進度。TypeScript、外部套件評估與完整建置流程仍需後續練習。
