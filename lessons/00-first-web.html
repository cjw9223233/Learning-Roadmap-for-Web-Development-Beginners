GUIDED PRACTICE / 00

從本機檔案，
看懂一次 HTTP 往返。

完成這份練習後，你會有一個自己修改過的 HTML 檔案，並能透過模擬器解釋請求、回應與資料變動。先預測，再操作，最後用證據說明結果。

更新：2026-11-18 · 離線可讀 · 依操作與理解調整進度

準備好就開始

  • 可儲存純文字檔案的編輯器，例如 VS Code 或記事本。
  • 瀏覽器與一個自己建立的練習資料夾。前半段不需安裝 Node.js、Python 或套件。
  • 所有資料均使用虛構設備；HTTP 模擬器完全離線，不呼叫真實 API。

1. 建立可辨識的檔案

在自己的練習資料夾建立 index.html，複製下方起始程式。請以 UTF-8 儲存；在檔案總管開啟副檔名顯示，確認檔名不是 index.html.txt。也可以先另存提供的起始頁，再用編輯器開啟。

<!doctype html>
<html lang="zh-Hant">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>巡檢起始頁</title>
</head>
<body>
  <main>
    <h1>車站設備巡檢</h1>
    <p>今天檢查的設備：A01 月台照明</p>
    <h2>巡檢步驟</h2>
    <ol>
      <li>確認設備位置</li>
      <li>記錄是否正常</li>
    </ol>
  </main>
</body>
</html>
預期觀察

雙擊檔案後，網址以 file: 開頭，頁面顯示『車站設備巡檢』。這是本機檔案，尚未公開上線。

2. 分辨分頁標題與頁面標題

只把 title 內的文字改成『我的巡檢練習』，儲存並重新整理。再只改 h1 的內容，重複相同操作。觀察兩個改動各出現在哪裡。

預期觀察

title 改變瀏覽器分頁上的名稱；h1 改變網頁內容的主標題。head 中的設定資訊與 body 中的可見內容負責不同事情。

3. 把閱讀變成可驗證的操作

將設備名稱由 A01 改成 B02，並在清單新增『檢查電源』。在重新整理前先預測畫面會多出什麼。開啟開發者工具的 Elements（元素）分頁，找出 h1、p 與 li。

預期觀察

畫面應呈現新設備名稱與新增清單項目。Elements 顯示瀏覽器解析後的文件結構；這與編輯器中的原始碼互相對照，但不是同一個視窗。

4. 看懂位址，而不只看畫面

先記錄 file: 網址。若已安裝 Python，可在自己練習資料夾開啟終端機，執行 python -m http.server 8000 --bind 127.0.0.1，再開啟 http://127.0.0.1:8000/index.html。若沒有 Python，先跳過此步，改做下一步的離線模擬器。

預期觀察

兩個網址可能顯示相似畫面，但只有 HTTP 版本會向本機伺服器取得回應。完成後在終端機按 Ctrl+C 停止服務。若連接埠已被使用，可改成 8001，網址也要同步更改。

5. 觀察一次真實 HTTP 請求（選做）

在 HTTP 版本開啟 Network（網路）分頁後重新整理，選取 index.html 文件列，尋找 Request URL、Request Method、Status Code 及 Response。再把網址改成 /does-not-exist.html。若正在使用 file: 版本，不必期待看見 HTTP 狀態碼。

預期觀察

由本機 Python 伺服器提供的現有檔案通常得到 200；不存在的檔案通常得到 404。快取可能產生不同觀察結果，應以實際顯示為準並檢查快取設定。此靜態伺服器不會自動提供 /api/inspections API。

6. 用離線模型理解資料變動

開啟 HTTP 模擬器，依序完成下方七個任務。每次先選預測結果，再按送出。比較請求文字、狀態、步驟說明與模擬資料筆數。

預期觀察

GET 成功讀取不會新增巡檢；有效 POST 在本模型會建立新紀錄；錯誤案例不會寫入。模擬器沒有真實網路、資料庫或登入，重新整理即回到一筆起始資料。

HTTP 模擬器的七個任務

先預測，再送出。模型資料只保存在當頁記憶體，重新整理回到一筆起始資料。真實服務的狀態碼與驗證契約可能不同。

開始操作模擬器 →

任務 1｜讀取巡檢清單

選擇『讀取清單』預設，先預測狀態碼，再送出。連續送出兩次。

完成操作後看解答

200 OK；兩次的模擬資料筆數相同。GET 在這個模型只讀取清單。

任務 2｜建立一筆巡檢

選擇『新增成功』預設，先記下目前筆數，再送出兩次。最後用 GET /api/inspections 讀取。

完成操作後看解答

每次得到 201 Created，兩次送出增加兩筆資料，ID 不同。POST 不保證冪等；實際產品需要另外設計重複提交的處理。

任務 3｜拒絕空白與壞掉的 JSON

選擇『輸入不合規』預設送出。再把 POST 內容改成只有一個左大括號 {，送出並觀察。

完成操作後看解答

兩種情況都回傳 400 Bad Request，但錯誤說明不同：前者是應用規則驗證失敗，後者是 JSON 語法錯誤。筆數不增加。400 是此模型選定的契約，實際 API 也可能用 422 等狀態表示部分驗證錯誤。

任務 4｜找到錯誤的路徑

選擇『路徑不存在』預設送出，再改回 /api/inspections 送出。

完成操作後看解答

不存在的路徑回傳 404 Not Found；改回有效路徑得到 200。本模型中的錯誤由路由查找產生，沒有執行資料寫入。

任務 5｜方法不被允許

選擇『方法不允許』預設送出，查看 Allow 標頭，再把方法改成 GET。

完成操作後看解答

POST /api/inspections/1 回傳 405 Method Not Allowed，Allow: GET 告知此模型允許的方法；GET 相同路徑可讀取起始紀錄。

任務 6｜伺服器回報失敗

選擇『伺服器失敗』預設送出，比較回應與模擬筆數。

完成操作後看解答

收到 500 Internal Server Error，表示有收到 HTTP 回應。本模型刻意在寫入前停止；真實系統遇到 500 時不能據此保證資料未寫入。

任務 7｜沒有收到 HTTP 回應

選擇『網路未連通』預設送出，觀察哪一步停止，並與 500 比較。

完成操作後看解答

沒有狀態碼。這是網路連線在抵達伺服器前失敗的教學模型，不能把它標成 500。真實網路逾時也可能發生在伺服器已處理之後，重送前應考慮重複寫入風險。

遇到卡點先檢查

瀏覽器顯示原始碼

先確認副檔名為 .html，並使用瀏覽器開啟。檔名與儲存格式比重新複製程式更值得先檢查。

改完沒有變化

先儲存，再重新整理；確認正在編輯的檔案與網址指向同一份。使用 HTTP 時再檢查快取。

中文顯示亂碼

檔案使用 UTF-8 儲存，且 head 包含 meta charset="utf-8"。兩者都要檢查。

localhost 無法連線

確認本機伺服器仍執行、連接埠與網址一致。只開啟 HTML 檔案不會自動啟動 HTTP 服務。

在 Network 找不到模擬 API

模擬器不送出 fetch 或真實 HTTP 請求。畫面的請求／回應是教學模型；要觀察實際 Network，使用步驟 5 的本機伺服器。

完成檢核

  • 保留一份自己修改的 HTML，能說明 title 與 h1 的差別。
  • 能描述 file: 與本機 HTTP 服務的差別，並知道 localhost 不是自動公開上線。
  • 完成七個模擬任務，記錄方法、路徑、預期結果與實際結果。
  • 能解釋 400、404、405、500 與無 HTTP 回應的差別。
  • 能說明模擬器沒有真實網路與持久資料庫，且 POST 重送可能重複建立資料。

完成實作後，再回到主教材第 0 階段勾選原有驗收。本頁不會自動修改進度。
